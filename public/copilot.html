AI Copilot · Live

A copilot that shows its work.

Bring Ollama, LM Studio, llama.cpp or any OpenAI-compatible provider. Choose exactly which files and diagnostics are eligible, inspect the assembled bundle, then review complete-file proposals as diffs before accepting an undoable edit.

Configure a provider Open the live overview

No provider by default

The app is fully usable without AI. The dock says no provider is configured instead of inventing an answer.

Two adapters

Native Ollama uses NDJSON /api/chat and /api/tags. The OpenAI-compatible adapter uses SSE /chat/completions and /models.

Context you can inspect

Active file, selection, tree names and Monaco markers are toggles. Other files are attached explicitly, and a character budget caps the bundle.

Seven modes

Chat, explain at three depths, debug, generate, review, tests and a learning mode that starts with hints.

Review before write

Proposals are complete files in codepilot fences. Unsafe paths are rejected; accepting applies one undoable edit and never saves automatically.

Honest failures

Auth, network, provider, CORS and rate-limit errors are distinct. Nothing is retried silently or replaced with a fake success.

Credentials

No key is compiled into the bundle. A typed key lives in memory by default and only reaches IndexedDB when “remember in this browser” is checked. A local proxy can hold keys server-side: point the base URL at it and leave the key field empty.

Privacy boundary

Context is assembled in your browser and sent only to the endpoint you configured, only when you press Send. CodePilot Lab operates no model proxy and receives no conversation content. Your provider's own retention policy still applies.

Cross-origin reality. Remote providers must allow browser requests (CORS). Free tiers rate-limit; the UI reports the provider's status rather than retrying on your behalf.
