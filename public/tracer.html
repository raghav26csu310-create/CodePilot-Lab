Execution Lab · Live

Watch a program actually run.

The tracer instruments Python with sys.settrace, records real line, call and return events, and reconstructs locals at each stop. Step forward and back, scrub the timeline, and inspect the call stack. Values you see came from the interpreter.

Open the Execution Lab Tracer limits

Real instrumentation

server/trace_python.py is the recorder. It emits line, call, return and exception events with a bounded event count.

Time travel over events

Step, play, pause and scrub across recorded stops. Back-stepping is a replay of recorded events, not a guess about state.

Locals with provenance

Type, value, scope, declaration and changed markers are derived from successive recorded frames.

Call stack

Each stop carries the real frame stack, so recursion and helper calls are visible.

Branch and loop observations

Observation cards are computed from event transitions that occurred, not from static analysis.

Other languages refused

Only Python has a real tracer. JavaScript, TypeScript, C, C++ and Java show an explicit unsupported message; Go is not offered by the runner.

Execution limits

The runner applies a compile timeout, an 8-second run cap, code/stdin/output character caps, a test-count cap and a trace-event cap. Jobs run in fresh temp directories and are tree-killed on timeout or Stop.

Not a sandbox. The execution service is a resource-limited loopback Node process. It is not a hardened security boundary and must not be exposed to untrusted networks. Public hosted execution is not offered as safe.
