The operator manual.

Everything below describes this repository. Where a feature depends on a local service or a model provider, the dependency is stated rather than assumed.

Install and run

npm install
npm run dev      # Vite, http://localhost:5173
npm run exec     # loopback runner, http://127.0.0.1:5310

npm run typecheck
npm run lint
npm run test
npm run build

Node.js 20 or newer is required for the toolchain. The frontend has no runtime secrets and no server dependency. The execution service is a separate local process.

Runtime availability is probed on the machine running the service. A missing compiler produces an explicit unsupported state; it is never replaced with sample output.

AI provider setup

Open Settings. Choose a preset or “OpenAI-compatible”, enter the base URL and model, then test the connection. Ollama's default is http://127.0.0.1:11434; allow the app origin with OLLAMA_ORIGINS=http://localhost:5173 if the browser is blocked.

Keys are optional for local models and live in memory unless you opt into browser persistence. A proxy can hold keys server-side. Remote providers must permit CORS from the app origin.

Workspace

Create or import a project, then edit files on the left. Saves go to IndexedDB (contents). Ctrl/⌘ S saves, Shift S saves all, P opens quick open, Shift F searches stored contents.

Execution and tracer limits

The runner caps source at 200,000 characters, stdin at 64,000, stdout at 96,000, stderr at 48,000, compile time at 20 seconds and run time at 8 seconds. Tracing caps at 2,500 events. Processes are tree-killed on timeout, Stop or shutdown.

Resource limits are not a sandbox. Only run code you would run in your own terminal. The service binds to loopback by default; a remote bind is refused unless the operator explicitly opts in with a token.

Code Converter

Conversion requires a configured provider. Review the diff before accepting. Save-as-new writes a new stored file; replace requires confirmation and never writes a linked folder on disk. Validation runs use the local execution service.

Practice grading

Visible cases are published in the UI and can be run repeatedly. Submissions use hidden suites in server/problems.mjs. The API returns only case indices, hidden flags, statuses and bounded visible stderr.

Feedback

Feedback is written to IndexedDB first. Set VITE_FEEDBACK_ENDPOINT to an absolute HTTPS URL to also POST the payload. The result panel reports local-only, delivered, or failed delivery with the HTTP status.

Deployment

The default public beta is frontend-only. Build with npm run build and serve dist/ with SPA rewrites. Execution is not available on static hosting; users who want it run the sidecar locally. See the deployment guide in the repository.

Troubleshooting

  • “Execution service offline” — run npm run exec and confirm http://127.0.0.1:5310/health.
  • Provider request fails — check the base URL, model name, key, CORS and the provider's own status. Nothing is retried automatically.
  • Projects disappeared — IndexedDB is per origin and per profile. Private browsing or clearing site data removes it.
  • Linked folder unreadable — re-grant permission or re-import. Saved IndexedDB content still opens.
  • Blank screen after an update — hard reload to clear a stale service worker or optimized dependency cache.
