1. Getting started

Local development

npm install
npm run dev:all
npm run typecheck
npm run lint
npm run verify

dev:all coordinates Vite, the API and the optional loopback execution/terminal companion. Without it, the three processes can also be started separately:

npm run api:dev
npm run dev
npm run exec

Create a project from Workspace, open or import files, and save. Browser projects live in IndexedDB and are per-origin/per-browser-profile. Account data and saved provider credentials can live in the API when PostgreSQL is configured.

3. AI Copilot

Open AI Copilot. Choose a chat mode, share only the active file, selection, tree names or Monaco markers you need, and attach additional files explicitly. The context preview is the exact character-bounded bundle. Copilot supports chat, explanation, debugging, generation, review, test generation and learning modes.

Model answers containing complete-file codepilot proposals require review before one undoable Monaco edit is applied. Saving remains explicit.

5. Project management

Project Vault creates, imports, duplicates, renames, favours and deletes browser projects. Deleting a project removes stored browser entries; it does not erase a linked device folder.

Project Atlas derives imports, exports, entry points, test files and language breakdown from real project contents. Activity & Diagnostics records real application events and live health probes for the API, execution sidecar, terminal and GitHub companion.

6. Terminal and execution

The integrated terminal is a real loopback PTY companion, not a browser simulator. It supports multiple sessions, PowerShell or CMD on Windows, cwd changes, history, resize and exit codes. The companion prints a per-start pairing token and requires an allow-listed Origin.

Security boundary: the loopback runner is a resource-limited local tool, not a hardened sandbox. It can access the machine account's filesystem. Never expose it to anonymous public users or run untrusted code on a shared host.

7. Deployment

One managed service

npm ci
npm run build
npm start

npm start serves dist/ and the API from one Node process, runs PostgreSQL migrations before listening, and serves /api/health/live and /api/health/ready. Set PORT or API_PORT, API_HOST, CORS_ORIGINS, DATABASE_URL, CREDENTIAL_ENCRYPTION_KEY and SESSION_COOKIE_SECURE=true for production.

Docker Compose

openssl rand -base64 32
CREDENTIAL_ENCRYPTION_KEY=<generated-key> docker compose up --build -d

Use a real HTTPS origin in CORS_ORIGINS and a deployment-managed PostgreSQL service for durable data. The included database is only a local Compose convenience.

8. Troubleshooting

  • HTTP 401: sign in again and verify the browser includes the HttpOnly session cookie.
  • HTTP 403: verify CORS_ORIGINS exactly matches the public HTTPS origin and Origin/CSRF headers are present.
  • HTTP 429: distinguish provider retry headers from application throttling. Quota-exhausted providers must be corrected or disabled; temporary overload can fall back before text streams.
  • HTTP 404: the provider model or endpoint is wrong. Test connection and model availability first.
  • Terminal offline: start the loopback companion, confirm /terminal/health, then paste the current pairing token from that process console.
  • Execution offline: start npm run exec; a hosted deployment cannot start a local compiler by itself.
  • Projects disappeared: IndexedDB is origin/profile-specific. Private browsing or clearing site data removes local projects.

9. Security and privacy

  • Platform provider keys exist only in server environment variables or the encrypted API connection store.
  • Never place secrets in VITE_* variables or commit .env.
  • Authentication uses session cookies, SameSite policy and CSRF Origin checks.
  • Production requires PostgreSQL and a persistent 32-byte AES-GCM credential key.
  • Browser project files are local-first; account/project server storage uses the API only when configured.
  • Terminal and execution features remain loopback/local unless separately hardened in an external isolated service.

10. FAQ and support

Does deployment start the terminal or execute public code? No. A public service must use a separate isolated container/VM runner. The repository's terminal and execution sidecar are host-machine developer tools.

Can Groq, OpenRouter or a custom endpoint be used? Yes, independently through the OpenAI-compatible adapter with that provider's base URL and model.

Can the app work without PostgreSQL or AI? Yes for local IndexedDB editing, but production API startup requires PostgreSQL and AI features remain explicitly unavailable until a provider is configured.

Where are logs? API requests have structured stdout logs and request IDs. Activity & Diagnostics shows browser-side events and live subsystem health.
